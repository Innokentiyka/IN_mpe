# Безопасность и эксплуатация

MVP проверяет права на каждом серверном запросе и пока предназначен для закрытого запуска/пилотирования.

## Реализовано

- Пароли хранятся в виде salted PBKDF2-HMAC-SHA256 хешей (600 000 итераций), не в открытом виде.
- Случайные непрозрачные сессии лежат в БД только как SHA-256 digest; cookie `HttpOnly`, `SameSite=Lax`, срок семь дней. Для HTTPS устанавливается `COOKIE_SECURE=true`.
- Все изменяющие JSON-запросы защищены связанным с сессией случайным CSRF-токеном. Приложение не включает CORS.
- Ограничены размер запроса и поля; SQL-запросы параметризованы; на вход действует ограничение частоты по IP.
- Администраторские и интервьюерские права проверяются на сервере. Интервьюер может сохранять результаты только назначенных ему интервью. Кандидат видит только собственный кабинет; оценки отдаёт только API администратора.
- Бронирование выполняется под SQLite `BEGIN IMMEDIATE`, проверяет вместимость и блокирует несколько активных записей у одного кандидата.
- Аналогично проверяется запись на мероприятия; администратор может отмечать посещение или отсутствие участника.
- Слоты разделяют интервью и аттестацию; запись на аттестацию доступна после того, как администратор установил статус «Аттестация».
- Сервер разрешает отдавать только белый список HTML/CSS/JS/брендовых изображений. Исходный код, база, dotfiles, `.git` и файлы конфигурации по HTTP недоступны.
- Экранирование динамического текста выполняется на клиенте; CSP и защитные HTTP-заголовки задаёт сервер.
- Текущая конфигурация по умолчанию слушает только `127.0.0.1`; база и аккаунты игнорируются Git.
- Лимит регистрации и входа хранится в памяти процесса и применяется отдельно по IP.

## Перед публичным запуском

1. Развернуть за TLS reverse proxy, выставить `COOKIE_SECURE=true`, не публиковать backend порт и настроить HSTS на HTTPS proxy. Поддерживать обновлённые ОС/Python.
2. В `privacy.html` указать подтверждённого оператора персональных данных, контакт для запросов, законное основание, сроки хранения/удаления, процедуру отзыва согласия и утверждённые тексты согласия. Эти сведения не предоставлены заказчиком, поэтому не выдумывались.
3. Подключить подтверждение владения номером через утверждённый канал (сейчас вход только по введённому телефону, SMS не настроены), а также процедуру восстановления доступа, удаление/экспорт данных по запросу, утверждённые сроки хранения и автоматическое удаление устаревших заявок. Для локального аварийного сброса пароля есть команда `python3 server.py reset-password +79990000000`; выполнять только оператору сервера после проверки личности пользователя.
4. Защитить доступ к SQLite-файлу и резервным копиям, включить регулярную проверку восстановления. Настроить отдельный административный доступ, аудит, мониторинг с ротацией логов и резервирование.
5. Rate limit сейчас хранится в памяти процесса; для нескольких workers или жёсткой защиты от распределённых атак перенести его в общий rate limiter.
6. Провести проверку настроек reverse proxy/HTTPS, авторизации между ролями, CSRF, XSS, нагрузки/гонок бронирования, восстановления БД и операций с данными перед настоящим набором.

На сервер пока не подключены email, SMS, VK API, СОС-диск, восстановление пароля, загрузка файлов и автоматические массовые уведомления. Заявки/уведомления сохраняются локально в БД и доступны пользователю/команде внутри кабинетов; никаких внешних сообщений система не отправляет.
